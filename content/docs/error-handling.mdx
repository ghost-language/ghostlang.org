## Syntax Errors

The first errors you are likely to run into are syntax errors. These include simple bugs where your code doesn't follow Ghost's grammar, like:

```typescript
1 + * 2
```

Ghost detects these while reading your code, before running any of it. When it hits one, you get an error naming the line, the column, and the token it choked on:

```
1:5: syntax error: unexpected token `*`
```

Parsing reports every syntax error it finds, not just the first, so one pass over a file tells you about all of them. If a file has any, none of it runs.

## Runtime Errors

Errors that can't be found by reading the code are found by running it. Since they can't be detected until then, they're called "runtime" errors.

Most runtime errors come from the evaluation of your code itself. They arise from code trying to perform an operation that Ghost can't do. A common one is a method that doesn't exist. If you call a method on an object and its class doesn't define that method, there's nothing Ghost can do:

```typescript
class Foo {
  bar() {
    //
  }
}

foo = new Foo()

foo.someRandomMethod()
```

If you run this, Ghost reports:

```
9:4:example.ghost: runtime error: undefined method someRandomMethod for class Foo
```

Runtime errors carry the line, the column, and the file they happened in.

Another common one is a name that was never defined. Unlike a syntax error, this is only noticed when execution reaches the line that reads it:

```typescript
print("this line runs")
print(message)
```

```
this line runs
2:7:example.ghost: runtime error: unknown identifier: message
```

Type mismatches are the third common shape — Ghost does not convert values for you:

```typescript
print("Ghost " + 1) // runtime error: type mismatch: STRING + NUMBER
```

Call [`toString()`](/docs/numbers#tostring) on the number, or use [`format()`](/docs/strings#format).

When a runtime error occurs, Ghost reports it and stops. Unlike some other languages, Ghost will not keep plugging away after a runtime error has occurred.

A runtime error implies there's a bug in your code and it wants to draw your attention to it.

## Creating Runtime Errors

Most runtime errors come from within the Ghost evaluator, but you may want to be able to cause your own runtime errors to occur. This can be done by calling the `ghost.abort()` function:

```typescript
ghost.abort("Something bad happened")
```

You must pass in exactly one argument, and it must be a string or `null`. A string raises a runtime error carrying that message; `null` does nothing at all, which lets a check that has nothing to complain about hand back `null` and be aborted on unconditionally.

## Values That Aren't Errors

Not every miss is an error. A few operations answer with `null` instead, and are worth knowing so you don't reach for error handling where a comparison will do:

- A list index that is out of range.
- A map key that isn't present.
- A string index that is out of range.
- A function that ends without a `return`.

```typescript
list = [1, 2, 3]

if (list[10] == null) {
  print("nothing there")
}
```
